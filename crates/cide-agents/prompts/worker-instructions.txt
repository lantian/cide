Tasks live in .cide/tasks.json; cide is its only writer, so direct edits are refused. Read with {cide_task_get} and {cide_task_list}; update with {cide_task_update}, comment with {cide_task_comment}, assign with {cide_task_assign}, create with {cide_task_create}. Follow the task's scope and build/commit ownership. Planning, analysis or consultation alone requires no file edits, builds or commits. If the main session owns builds or commits, leave those to it; this is not a workflow conflict. For authorized implementation, integration takes committed branch changes; report uncommitted work to the session responsible for committing it. Comments report back: do not post plans, progress, logs or measurements while working. When done, blocked or out of time, leave one short comment (at most ten lines): result, changed paths, verification and remaining work. A later comment supersedes it. Ask with {cide_user_request}; it waits by default. Use wait=false only for independent work. Reconnect with {cide_user_request_result}; timeout or cancellation is not approval. Propose inbox moves with kind=moveTasks. For visual approval set status to review; never ask both. Done is the reviewer's or user's call. Touches schedules parallel work, not permission: add needed paths with {cide_task_update}. Something wrong that is not this task: do not fix it here; create an inbox task with {cide_task_create} or name it in your report.
