# GitLab reviews

Connect accounts in **Settings → Git → GitLab accounts**, then open **GitLab merge requests** on the activity rail. Account connections and review exclusions are managed in global Settings. Use an HTTPS instance URL (including an installation prefix when needed) and a personal access token with `api` scope. Multiple accounts and self-hosted instances are supported. API access follows the Git proxy scope in Cide's proxy settings.

The inbox provides **To review**, **Created**, and **Assigned** views with state, project, account, and text filters. Rows show MR state, project, branches, author, comments, and last update, ordered by most recently updated. Paste a GitLab MR URL to review a repository that is not open locally. The command palette's **Open GitLab merge request by URL…** opens a focused URL dialog: paste with Ctrl+V and press Enter. After a successful Cide push, an existing MR can be opened; otherwise Cide offers GitLab's browser creation form.

Each open review adds its own GitLab icon to the left activity rail. Its sidebar shows the changed-file tree, assignees, approval controls, and filtered change totals. A highlighted overall approval status shows whether the MR is approved, still needs approvals, or has no approval requirement. This is separate from your own approval. The status refreshes after approval actions and every 30 seconds; new commits or an unavailable API are shown explicitly. Overview, Discussions, Activity, and Pipelines buttons open modal dialogs. Close a review with the × in its sidebar header. Changed files open as ordinary workspace tabs using Cide’s existing diff viewer, alongside your local file tabs. The shared split/unified preference, syntax highlighting, folding, and change navigation apply to MR diffs too. Use Alt+PageUp / Alt+PageDown to open the previous / next visible MR file. Click either side’s line number to start an inline thread. Threads appear beneath their source lines, can be collapsed, and collapse automatically when resolved. File rows show resolved and unresolved thread counts. MR source and base files open in separate tabs pinned to their commit; refreshing a review keeps existing tabs on their original revision. Comments and replies are posted immediately; failed submissions retain their text. Approval is checked against the reviewed commit SHA. Refresh explicitly when new commits appear.

**Open MR source file** and **Browse MR source** create an isolated, read-only review checkout using installed Git over HTTPS with the configured Git proxy. Fetches use the connected account token without saving it in Git configuration or command arguments, and retain Git’s TLS and connection diagnostics if they fail. Failed source preparation can be retried from the source tab. In source files, F12 navigates to definitions and Shift+F12 lists references when the corresponding language server is available. **Open base file** shows the merge-base revision. **Open local working-tree file** is available when reviewing from a local project and verifies that its remote matches the MR's source project before opening a file.

Review checkouts and their language services are pinned to commit SHAs, including when different windows review different revisions. Closing the MR closes its associated document tabs across windows, cancels any active fetch and its helpers, stops its services and removes all its temporary checkouts. Normal shutdown removes them too; the next startup recovers abandoned checkouts after a crash. GitLab review resources are separate from project and agent worktrees. Saved review tabs contain identities, never temporary paths or file contents.

**Review excluded files** is a global setting under Git. It defaults to `**/*.pb.go` and `**/*_grpc.pb.go`; supported wildcards are `*`, `**`, and `?`. Filename patterns without a slash, such as `*.pb.go`, match at every directory depth. Exclusions affect both the changed-file and full-source trees, file navigation, and file/addition/deletion totals. **Show excluded files** temporarily reveals them for a review. Threads on excluded files remain in Discussions. Local Git changes are unaffected.

The overview identifies assignees, reviewers, and approvers with clickable GitLab profiles. Descriptions, discussion replies, and chronological activity render Markdown and sanitized HTML.

Pipelines group jobs by stage, highlight statuses, show the selected job, and link downstream pipelines. Archived traces are fetched when available, including HTTPS storage redirects without forwarding the token. Erased or unavailable archived logs show their reason and a GitLab link. Select a job to read its log with ANSI colors and collapsible GitLab CI sections, filter lines, or follow running output. Files and logs are limited to 8 MiB per response; larger resources can be opened in GitLab. GitLab may also omit oversized diffs; the review marks incomplete totals rather than treating omitted changes as zero.

Account tokens live in a separate, permission-restricted GitLab state file and are never sent back in the account list or saved with workspace tabs. Disconnecting an account closes its reviews and removes its saved token.

## Verification

Automated checks: `cargo test -p cide-gitlab`, `cargo check -p cide-app`, `cargo xtask codegen --check`, `cargo xtask contract-check`, `pnpm --dir ui run check:gitlab`, `pnpm --dir ui run check:gitlab-render`, `pnpm --dir ui run check:gitlab-dom`, and `pnpm --dir ui build`.

For live acceptance, connect a test account, open both a local and an unrelated/fork MR, post and reply to an inline discussion, resolve it, approve, and inspect running job output. Push a fresh branch and follow the creation prompt. Review two different SHAs in separate windows, then close the MR and quit Cide; verify its temporary checkouts are gone and the original repositories are untouched. Also check light/dark themes and a narrow window.
