# Which check covers what you touched

The per-surface routing table that used to live in `CLAUDE.md`. Each section names the
surface (the files and symbols that belong to it), what to run after touching it, and the
silent-failure classes that surface has already paid for. `CLAUDE.md` keeps a one-line
index into this file; the prose here is the part that matters when you are actually in the code.

## Running the suite

Everything CI runs, in CI's order:

```sh
cargo fmt --all --check
cargo --locked xtask contract-check
cargo build --locked --workspace
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo --locked xtask codegen --check
pnpm --dir ui exec tsc --noEmit
pnpm --dir ui run check:<name>          # every check:* script in ui/package.json
pnpm --dir ui build
```

- **One Rust test:** `cargo test -p cide-git branches`. `--locked` matters (a re-resolved
  lockfile is the drift class CI exists to catch); `cargo xtask` is a `.cargo/config.toml`
  alias, so global flags lead: `cargo --locked xtask codegen`.
- **`#[ignore]`d tests are ignored on purpose.** Most spawn the real `claude` — they need the
  binary on PATH, an authenticated account, network, and they spend the user's own quota. The
  rest is `cide-pty`'s 1 GiB soak. Run them deliberately: `cargo test --workspace -- --ignored`.
- **The frontend has no test runner.** `ui/scripts/check-*.mjs` *are* the suite: each compiles
  a deliberately import-free module with the TypeScript in `node_modules` (or SSR-bundles an
  entry through Vite) and asserts on the output. **A check that greps source must strip its
  comments first**, and in this repository that is mandatory rather than tidy: the house style
  is to name the failure a rule prevents, so the words a check looks for are exactly the words
  its own documentation contains. Three assertions have now passed by matching their own
  explanation — `check:diff-render` on a package name in prose, and `check:docker` twice in one
  sitting on `height: 100%` and on `spawnPlans.ts`. Adding a `check:foo` script to
  `ui/package.json` is enough — CI enumerates them rather than listing them. Several modules
  are import-free *so that* their check can compile them standalone; keep them that way.
- **Linux is the only platform cide has ever run on.** `docs/platforms.md` is the record: what a `cfg` arm does on macOS instead, which guarantees have no equivalent there (`PR_SET_PDEATHSIG` above all), and what still needs a Mac. The `macos` CI job is advisory until it has passed once.
- **The macOS arms type-check from here for nine of the twelve crates, and it is worth doing before touching a `cfg`-gated one.** `docs/platforms.md`'s *Type-checking for macOS from Linux* has the command; it uses `scripts/darwin-cc.sh` and `DOCS_RS=1`. **`cide-app`, `cide-git` and `xtask` are excluded** — `git2` is `vendored-openssl`, so they build OpenSSL for Darwin and that needs a real cross toolchain. So it covers `cide-core`'s `child_env` arms and every other domain crate, and it does *not* cover the crate that links tauri: the two errors a Mac reported in M16 were both in `cide-app` and this would have caught neither. It proves nothing about linking or runtime, and it is not a substitute for the `macos` CI job.

## By surface

### `keys/`, a default binding, `cide-core::commands`

**Touches:** `keys/`, a default binding, `cide-core::commands`

`check:keys`, `check:commands`, `check:switcher`, plus `cargo test -p cide-core commands`. **Every tier above `TIER_SUBSEQUENCE` matches at a word boundary, and there is deliberately no title-*substring* tier** — one existed and could only fire for a match strictly inside a word, which is an accident of spelling rather than a claim on the word. Adding `docker.compose.recreate` silently displaced *New branch…* as the first answer for `create`, because `Recreate` contains it and that tier outranked the keyword `git.branch.new` declares. The trap was dodged once before by renaming a command (`git.tag.create` → `git.tag.new`); when the word belongs to somebody else's vocabulary, renaming is not available and the tier is the thing that has to go

### A non-Latin keyboard layout

**Touches:** a non-Latin keyboard layout — `keys/latin.ts`, or anything that reads `KeyboardEvent.key`/`keyCode` for a chord

`check:latin`, `check:keys`, `check:terminal-keys`. WebKitGTK reports the *produced character* as `key` and `keyCode 0` for a non-Latin keyval; only `code` is physical. The gate reads `code`, so it was never the bug — xterm (encodes Ctrl+letter from `keyCode`), CodeMirror (`key`, falling back to `base[keyCode]`) and every `ev.key === 'f'` rule in this app were, and under a Russian layout Ctrl+C did not interrupt, Ctrl+Z did not undo and Ctrl+V reached bash as `quoted-insert`. `latin.ts` rewrites a chord keydown **in place**, from both gate entry points, so anything reading `key`/`keyCode` under Ctrl/Alt/Meta *after the gate's window listener* sees the US face — a capture listener on `window` registered *before* the gate's does not, so register such a listener on `document` (the OpenSpec tab's Ctrl+F is the precedent). Typing is never rewritten: a check that started pinning `key` under a chord to the layout's character would be pinning the bug, and one that pinned an unmodified `key` to the US face would be breaking every text field

### Push

**Touches:** push — `cide_git::push`'s `preview`/`push`/`check_lease`, `PushDialog`, `pushModel`, `pushStore`, `pushRun`

`check:push`, `check:branches`, plus `cargo test -p cide-git --test staging -- preview lease blocked diverged publish`. Three surfaces raise the dialog — the palette, the branch popup and *Commit and Push…* — and every one of them must go through `openPushDialog`, because two routes to one gesture that disagreed about whether it asks first is the split M20 already paid for here. Two silent-failure classes live in this surface. The **preview must describe the push that happens**: it resolves the remote with `default_remote` and spells the refspec exactly as `push` does, so a preview that derived either independently would draw a dialog that is internally consistent about a different push — and the count is `commits.length + more`, never `BranchInfo::ahead`, which is measured against the *upstream* and is zero for the publish case the dialog most needs a number for. And **force is a lease**: the binary route hands git `--force-with-lease` bare (an oid captured when the dialog opened is stale the moment anything else fetches), while the libgit2 route has no lease at all and cide performs the comparison itself in `check_lease` — delete it and the `+` refspec silently deletes whatever somebody else pushed, reporting success

### The change column

**Touches:** the change column — `editor/change*`, the `.cm-gutters` reservation

`check:change-bars`, then `check:editor` and `check:blame`, which pin the same reservation and the same extension array. The markers are diffed **in the webview**, against HEAD's blob and the *live* document — `git_diff_file` reads the file on disk, which is wrong for every unsaved buffer, and that is the state the editor is in whenever the column is most wanted. Four silent-failure classes live here: the HEAD blob must be split **exactly as CodeMirror splits a document** (`splitBaseline`) — on all three break shapes, or a CRLF file keeps a `\r` on every line and paints the **whole file** modified; and *keeping* the empty line after a final newline, because `Text` keeps it and the diff pane's `splitLines` correctly drops it, so borrowing that rule puts a phantom addition on the last line of nearly every file in the repository; the bar rules must stay **three classes deep**, or `highlightActiveLineGutter` paints over the marker on the one line the user is editing; and `revertPlan`'s `eat` decides which surrounding line break a removal consumes, which is the one operation here that **destroys** the user's text rather than mispainting it, and the revert round-trip over sixteen block shapes in `check:change-bars` is its only automated defence

### A role's colour, or who a comment is signed by

**Touches:** a role's colour, or who a comment is signed by — `cide_ipc::agents::{AGENT_HUES,hue,AgentDef::color}`, `defs.rs`'s `color` arm, `--agent-*` in `tokens.css`, `AgentsPanel/model.ts`'s `agentColor`/`rosterColors`/`authorColor`, `TasksPanel`'s `Chip::agent` and `.logAuthor`

`check:theme` above all, then `check:agents`, `check:agents-render`, `check:ui-scale`, plus `cargo test -p cide-ipc agents` and `cargo test -p cide-agents` — where **`claude_corpus` staying green is the claim**, because `color` is Claude Code's own key and cide *reads* it without modelling it: `read_definition` takes the value on the way past and leaves it in `extras`, so `render` still writes the user's own line back and `KNOWN_KEYS`/`canonical_key`/`AgentDraft`/`AgentField`/`tools.rs` are all untouched. Five silent-failure classes. **The reserved colour is reserved by absence** — `--agent-orchestrator` is not in `AGENT_HUES`, so no hash can reach it (the modulus indexes that list) and no definition can name it (`hue` refuses every word outside the eight, `"orchestrator"` included); a ninth entry plus a rule saying *not that one* is the same claim written where it can be forgotten. **The order of `AGENT_HUES` is API**, and `check:agents` pins the TS list against the Rust one *in order* rather than as sets — a derived colour **is** an index, so two lists holding the same eight words in a different order agree on every set comparison and recolour every uncoloured role in every tracker. **A colour is a `var(--agent-…)` and never a hex** (`laneColor`'s rule), and every name must be declared in **both** palette blocks, or an undefined custom property paints the inherited colour and nothing is logged. **The chip's tone is a claim about the run and the label's colour is a claim about the role** — recolouring the chip itself would trade a fact for a name, so the colour lands on the word and `check:agents-render` asserts both halves in one pair of stories. And **the user's arm answers `null` on purpose**, so `.logAuthorUser`'s `--accent` goes on winning: it is deliberately outside `check:theme`'s separation gate, because "You" is a word no reader confuses with a role's name. The three gates on the palette are measured, not judged — pairwise `>= 70` redmean, the orchestrator `>= 100` from all eight, every one over `INK_FLOOR` on **both** `--panel` and `--sel` — and `smokeEntry`'s colour readers find the tag before reading `style` out of it, because JSX prop order decides attribute order and one ordered regex matches nothing the day `style` moves. **The Settings picker (M77) is a control over that carried key and not a field** — `agentsDraft.ts`'s `COLOR_KEY`/`AGENT_HUES`/`colorOf`/`unknownColor`/`withColor`/`metaExtras`/`withMetaExtras`, drawn by `AgentsSection.tsx`'s `ColorChoice`, gated by `check:settings-agents` — so `AgentField` still has twelve variants and no Rust field moved. Four more silent failures. **One key, one editor**: the Meta rows are built from `metaExtras` and therefore hand back a list with no colour in it, so an edit there drops the key unless it goes through `withMetaExtras` — and a `color` row typed into Meta by hand is discarded in favour of the picker's, because two editors of one key disagree the moment they differ. **Automatic removes the key and never blanks it** (`cide_ipc::llm`'s rule), keeping its **position** (`isDirty` compares the extras array in order, so moving a key reports a change nobody made) and its **spelling** (`Color:` stays `Color:` — cide matches it folded and must not rewrite a committed file to suit itself). **An unrecognised value is a note naming the word, never a refusal and never a silent reset**: the role runs on its derived hue and the key is left exactly as the file has it until somebody chooses. And **`data-audit` on a component is not a hook** — hyphenated attributes are exempt from JSX excess-property checking, so `tsc` accepts one on `Note`, which does not spread its props and drops it before the DOM; put it on a wrapper, or a render check looks for an element that never existed

### The board's payload, or anything that opens a task's card

**Touches:** the board's payload, or anything that opens a task's card — `cide_ipc::{TaskRow,TaskDetail}`, `cide_tasks::{row_of,detail_of,search}`, `TaskStore::board`, `task_get`/`task_search`, `emit::tasks_changed`, `TasksPanel/model.ts`'s `TaskDetailView`/`matchesQuery`, `adapt.ts`'s `row`/`adaptDetail`, `TaskDetailPending`

`check:agents`, `check:agents-render`, `check:selectors`, `check:theme`, plus `cargo test -p cide-tasks` and `cargo xtask codegen --check` — which is the **only** shape gate here, because `contract/*.json` are flat *name* arrays and `contract-check` stays green through any payload change. The board carries **rows**: it used to carry every word ever written into a tracker, and Tauri delivers an event by inlining the payload into a JavaScript *source string* and `eval`ing it per webview on the GTK main loop (`tauri`'s `event::emit_js_script`) — 2.25 MB of it, at 10.2 ms to parse as source against 2.9 ms as JSON, per window, per comment an agent wrote. Now 50 KiB. `cide-pty`'s coalescer rule, arriving three orders of magnitude larger. Five silent failures live here. **`rev` must stay on `TaskBoard::Ready`** — `newerBoard`'s drop rule is `Number.isFinite(next.rev) && next.rev > current.rev`, so a missing one judges *every* snapshot not-newer and freezes the panel for the rest of the session, with no type error and nothing logged. **The two counts have one producer** (`row_of`), which is why `TaskDetail` nests its row rather than inlining it and why the fixture *derives* them: a second place computing a number gives two plausible answers, and a count is only visibly wrong next to the list it counts. **A card may never be built from a row** — every content field renders a *sentence* when empty (`No description.`, `No comments yet.`, a history disclosure simply not drawn, an Attachments section gone label and all), and worst, `startEdit` seeds the body editor from `body`, so an unfetched one opens empty, reports dirty on the first keystroke and commits that emptiness over the real text. `TaskDetailView` makes it a compile error; `TaskDetailPending` is the one component allowed a row, because it draws no content field at all. **Search runs in Rust** (`cide_tasks::search`, id + title + body, never the comments) because the body left the board: a local id-and-title filter would draw *No tasks match "…"* over a task whose description contains exactly what was typed. And **`matched` is nullable** — `null` is *no query*, including while an answer is outstanding, so `listEmpty` cannot claim anything about a search that has not run; `list-search-pending` asserts the row list is byte-identical to the unnarrowed one. Note `check:agents-render`'s attachment loop exempts stories by **name**, so a change that made every card draw no tiles would make it pass *harder* — the pending card's absences are therefore asserted beside the sentence that names the fetch

### The tracker's storage

**Touches:** the tracker's storage — `cide_tasks::{TASKS_DIR,content_dir,content_path,write_content,remove_content}`, `ContentCache`, `TaskStore::{compose,put,update,search}`, `merge_row`/`merge_content`/`newest_content_stamp`, `validate_content`/`repair_content`/`recovered_creator`, `read`'s ladder (`migrate`/`v1_to_v2`), `attachments::{dir,legacy_dir,path_of,relocate}`, `cide_ipc::{TaskContent,TaskFile,TaskAttachment::relative_path}`

`cargo test -p cide-tasks` (64 of them), `cargo test -p cide-ipc tasks`, `cargo test -p cide-hook`, `cargo test -p cide-app dotcide`, plus — the one that matters — `CIDE_TRACKER=<project> cargo test -p cide-tasks a_real_tracker -- --ignored`, which **copies** a real `.cide/` and converts the copy: every fixture in the file was written by somebody who already knew the format, and a four-month-old board has tasks from four builds of cide in it. `.cide/tasks.json` is an **index** since M68 (schema 2) and each task's body, log, history and attachment records are `.cide/tasks/<id>/task.json`, with the bytes under `.cide/tasks/<id>/attachments/`: 2.67 MB rewritten per mutation became 77 KB, 36× less. Six silent failures. **A content file this process has not loaded is never written** — that sentence is why nothing here reasons about a partially-known board, and it is what bounds the merge to the `dirty` set. **Content is written before the index**, because the worst interrupted state must be an orphan directory the reader ignores and not a row naming content that was never written — a task whose body and whole conversation read as empty. **An orphan content directory is ignored, never adopted** (`delete` writes no tombstone, so adopting one resurrects every deleted task at the next open) while a row with no content file renders. **A content write bumps its row's `updated_unix_ms`** (`newest_content_stamp`), or a comment stops moving its task's merge rank and its position in the panel. **`ContentCache` rolls back through an undo log, not a clone** — cloning would copy every loaded body per mutation, the exact cost the split removed — and `Undo::was_removed` is load-bearing: without it a `delete` whose `validate` failed leaves its id in `removed` and the next flush takes a live task's content. And **`reconcile` migrates**, because a `git checkout` of a pre-M68 branch puts a schema 1 file back under a running cide; an arm that dropped the lifted content merges the index fine and leaves every task reading as empty. `TaskRow::of` lives in `cide-ipc` on `TaskAttachment::relative_path`'s stated rule (two crates need it, one may not depend on `cide-tasks`), and `TaskDetail` nests its row so the two counts keep one producer. Conversion happens **on open, outright** — `TaskStore::open` argues the trade against asking first — so a teammate on an older build reads a converted tracker as *unreadable*, which is correct and is a real upgrade consequence. `cide-hook`'s matcher and `dotcide::classify` both spell these paths themselves and must move with them

### Opening a run

**Touches:** opening a run — `AgentRegistry::open_plan`, `agents_run_open`, `Harness::continue_spec`, `SplitIntent::Continue`, `Pane::continues`, `AgentsPanel/openRun.ts`, the `history` attach

`cargo test -p cide-app -- agents lifecycle cmd::pane cmd::session`, `cargo test -p cide-agents`, `cargo test -p cide-pty`, `check:agents`, `check:agents-render`, `check:attach`, `check:rows`, `check:detached`. Open is a **question** to Rust (`RunOpen`: mirror the live child, continue the conversation in the real harness, or a sentence) and the pane is still built by the gesture through the spawn-plan path — the deleted `agent_open_pane` note in `cmd/agents.rs` says why, and it is unchanged. Four silent failures live here: a conversation is filed under the run's **worktree**, so a resume from the project root finds nothing (`HarnessSession::cwd`, and `lifecycle::entry_for` reads it); a plan that *spawns* must skip `TerminalPane`'s adoption of the domain session, or a retained exited screen is shown where `--resume` was promised; a history replay on a host with a saved buffer paints the transcript twice (`attachModel.historyRequest` is the rule, `check:attach` pins it); and two harness processes on one conversation write one transcript from two places — the registry's `viewers` table is the only guard for opencode, and `owns_session` answering false for `Interrupted` is what lets a pane close the `claude --resume` it started. **The opencode stream's rendering** — which is mimo's too, one renderer for both flavours (M81) — (`harness/opencode.rs::render_event`, `RenderState`, `RUN_COLS`, `SpawnSpec::fixed_size`, `terminal/runLinks.ts`, `LogDetailCard`) is pinned by `cargo test -p cide-agents`, `cargo test -p cide-pty` and `check:json-log`: the run's mirror is wide and **never resized** because `vt100` truncates rows and clears wrap flags on resize, the live marker is erased by the next line with a cursor-up that assumes the marker never wrapped, and the `#7` handle at the end of a tool line is plain text on purpose — an OSC 8 link is dropped by every replay. **A block of reasoning is one collapsed row** since M62 — and the first thing to check when no row appears is that the child was asked for the events at all: opencode gates its `reasoning` event on `--thinking` (`m = j.mini ? (j.thinking ?? true) : (j.thinking ?? false)`, measured on 1.18.31), so cide passes it beside `--format json` and for the same reason — it is the channel's content, not a display preference. Without it a run that spent 6,429 reasoning tokens emitted not one reasoning event, and the row was correct and invisible. The row is — `∴ thought  4.1s #8`, spelled by `render::thought_line` for *both* harnesses and drawing none of the thinking, which now survives only in the ring. Four things about it are silent if got wrong: `runLinks.ts`'s glyph class must keep `∴`, or every row shows a handle no click resolves (`check:json-log` reads the row's format string out of `render.rs` and drives the parser over it, comments stripped first because that file's prose spells the row); a duration is **stated** (opencode's `part.time`) before it is **measured** (the silence since the last line that drew anything, which is all codex has — it records no clock on any item), and where neither is available the row prints *no* duration rather than `0ms`, which is why `RenderState::now_unix_ms` is an `Option` and not a `u64` that defaults to 1970; that clock is read **once** in `stream_hook` and given to `logring::record_at` and the render state alike; and keeping reasoning is what `logring::BYTES_CAP` is for — `CAP` counts lines, a thinking block is kilobytes, and the honest cost is that a run which thinks hard ages out its own earlier tool handles. **The qwen harness** (`harness/qwen.rs`, `cide_app::event_tap`, `lifecycle::transcript_of`) is pinned by `cargo test -p cide-agents` and `cargo test -p cide-app event_tap` and, for the facts a dead endpoint could not measure, by `#[ignore]`d real-CLI tests: the event FIFO is made **before** the fork and opened **non-blocking** (a blocking open waits for ever on a child that died first), and a `result` event is the only end of a turn — a `message_stop` is one message of a tool-calling turn, run 06202dd6's lesson one harness over. **The codex harness** (`harness/codex.rs`, and `harness/render.rs`, the marker discipline and string helpers it shares with opencode's rendering) is pinned by `cargo test -p cide-agents`, `check:agents`, `check:settings-agents`, and by two **quota-free** real-CLI tests — `cargo test -p cide-agents --test real_codex -- --ignored --skip a_real_turn` renders the model's prompt input and reads the MCP table without calling a model, so run them on every change there. A run is one `codex exec --json` child per turn, opencode's shape, because the TUI has no dual output and codex's hooks live only in files cide will not write. Two silent failures: every string on a `-c` override goes through `toml_string`, because a value is parsed as TOML first and a brief that reads as another type is refused outright while one with a raw newline is not a string at all; and the run's `CIDE_RUN`/`CIDE_AGENT_SOCK` are spelled into `mcp_servers.cide.env.*` as well as the child's environment, because codex starts an MCP server with a *whitelisted* environment — drop either and the bridge starts, scopes itself to nothing, and every tracker tool answers nothing

### What a resumed run's pane opens onto

**Touches:** what a resumed run's pane opens onto — `replayed_run_log`/`replay_rows`/`line_stamp`, `saved_screen`/`save_screens_to`, `RESTART_SEPARATOR`, `SpawnSpec::preload`, `cide_agents::ERASE_MARKER`

`cargo test -p cide-app -- agents`, `cargo test -p cide-pty`, `check:json-log`, `check:attach`. A resumed `opencode` or `codex` run is a **new cide session** (`resume_point` answers `rebind: None` — their conversation id is the CLI's own), so its mirror, its sinks and its `logring` ring are all fresh and the pane shows nothing of what came before. **Touches:** rewriting a session's output — `cide_pty::LineRender`/`Rendered`, `render_lines`, `cide_core::jsonlog`, `lifecycle::json_log_render`, and the click-to-expand road — `logring`, `session_log_detail`, `terminal/logLink.ts`, `chrome/LogDetailCard`, `chrome/logDetailModel`

### The remote surface

**Touches:** the remote surface — `cide-remote`, `cide_ipc::{remote,screen}`, `cide_pty::screen`, `cide_core::remote`, `cide_app::remote`, `cmd/remote.rs`, `emit.rs`'s tee, `windows.rs`'s awaiting map, `settings/RemoteSection`, `contract/protocol.ts`, `cide_core::remote::pairing_qr`

`cargo test -p cide-remote` above all — it binds a real loopback socket and speaks the real protocol against a `FakeHost`, which is why it is the crate's whole end-to-end coverage and why **none of it is `#[ignore]`d**: a socket needs no binary on PATH. Then `cargo test -p cide-pty` — whose existing tests must pass **unmodified**, the `Transport` seam's rule applied to a second reader of the mirror — plus `cargo test -p cide-ipc -- remote screen`, `cargo test -p cide-app -- remote emit windows`, `cargo test -p cide-core -- remote workspace`, `cargo test -p xtask protocol`, `pnpm --dir ui run check:remote` — which **strips comments before it searches anything**, mandatory here because `RemoteSection.tsx` uses the word *token* five times explaining why it never renders one, and whose own first draft failed on that trap from the other side when a lazy block-comment regex ate the nav entry it was looking for — and `cargo --locked xtask codegen --check`, the only gate on `contract/protocol.ts`. `./target/debug/cide-headless remote` prints what a launch would bind and who is paired, `cide-docker`'s shape for `cide-docker`'s reason. **The wire has a second implementation**, in `../cide-mobile`, and two things keep the pair honest: `contract/seal-vectors.json`, regenerated by `cargo test -p cide-remote --test vectors -- --ignored` whenever the transport changes — a vector that moved is a wire that moved and every paired device is about to stop working — and `crates/cide-remote/examples/fake_cide.rs`, a real server that repository's end-to-end test drives over loopback. Neither `contract/protocol.ts` nor the vectors are checked by CI against that repository, so **run its `npm run check` after touching this surface**; the failure otherwise is a phone that connects and goes quiet, which is also what a bad network looks like. Six silent-failure classes live here. **A `Workspace` must never cross this wire** — it carries `Settings`, and `Settings` carries provider API keys and proxy passwords in plaintext, which is why `workspace.json` is 0600; `workspace-changed` is teed as a bare `rev`, the DTOs cannot name the tree, and `a_projection_carries_no_credential` plants a key and greps every frame because "cannot name it" stops being true the first time somebody adds a field. **The phone polls the mirror and never attaches a sink**: `cide-pty`'s backpressure is structural, so a sink would make a device on a train block the coalescer, then the reader, then the kernel buffer, then `claude` — and `ack` from inside `deliver` deadlocks the one thread every byte of every session flows through. **Paging scrollback moves the shared viewport**, which `reattach_state` and `screen_state` render from, so the restore is behind a drop guard and is asserted on the *bytes* rather than on `scrollback() == 0` — `parking_lot` does not poison, so a panic mid-walk would otherwise leave the next re-docked pane painting history. **A wide cell emits its glyph once and its continuation never**, or every CJK line slides one column right per glyph with all the text present; and the trailing-blank trim stops at a space that has a background, an underline or the inverse bit, because those are a selection and trimming them frays the right edge of the one thing being looked at. **The tee is bounded and `try_send`** — the threads reaching `emit.rs` are the hook applier and the GTK main loop, so a full queue is a `Desync` to the device and never a wait. And **a device reports an acknowledgement one session at a time, never a set**, `ui/src/panes/awaiting.ts`'s rule: the set travels *to* a device whole and *from* one entry by entry, because a surface that has observed nothing would otherwise report its empty set and clear every marker in the application. Three more live in the **pairing QR**, and all three produce a code that looks right and scans badly, which is the worst shape available because the person holding the phone cannot tell a bad symbol from a bad camera angle: `shapeRendering="crispEdges"` is load-bearing, since antialiasing greys a module boundary and a scanner thresholding a photograph of that reads the grey as whichever side it lands on; the four-module quiet zone is part of the symbol and is drawn inside the `viewBox` so no surrounding layout can eat it; and both colours are **stated** rather than inherited from the theme, because a scanner can invert and not every one does. `check:remote` asserts each, and `cargo test -p cide-core remote` asserts the *matrix* — the three finder patterns in the three corners a scanner looks for, and the fourth corner that must not have one, which is the one assertion a transposed or flipped grid cannot pass. `qr` is an `Option` and the typed code is drawn whatever happens to it: an encoder able to block a pairing that has nothing wrong with it is the only way this feature could make things worse. **The stop must not be skippable** (M74): `RemoteServer::shutdown` takes `&self` and **joins** the tasks it aborts, because it consumed `self` and the caller reached it through `Arc::try_unwrap` — which fails whenever the event pump holds its clone, so the losing arm dropped a refcount under a comment claiming the sockets closed anyway, the accept loop kept the `TcpListener` for the life of the process, and every later start answered *port already in use* against cide's own orphan. Terminal with a configured port, because one somebody typed is a promise to a device and `bind_somewhere` refuses rather than sliding off it. `a_stopped_server_gives_its_port_back_immediately` re-binds a **fixed** port three times holding a second `Arc` across each stop; `:0` twice would pass against a server that never stopped. **And it must not be reachable when nothing asked for it** (M76): a `#[tauri::command]` that is not `async` runs its body on the **GTK main thread**, and `emit_going_away` waits — for the aborted tasks, and for the connections to drain — while every host call in flight is blocked on an `app.emit` waiting for that same thread, so a stop from a command freezes the window for the drain timeout. `reconcile` therefore compares what is bound against what is asked for (`same_socket`, pure and tested) and leaves a matching listener alone, which is also correct on its own merits: opening and cancelling a pairing window change *who may pair*, which the running server reads out of the device store at every handshake, and restarting for them disconnected the phone that had just used the code. That stall is new because M74's fix is what made `shutdown` actually wait. And the **pairing payload carries at most `MAX_INVITE_HOSTS` addresses**, because cide offers every private one it has — ten on a developer's machine, nine of them docker and VPN bridges — which made the QR a 69-module symbol at 2.5 screen pixels per module (silently unscannable: a live viewfinder and nothing else) and made the phone walk nine fifteen-second timeouts behind a disabled spinner. Both numbers are measured and in the code, because the intuition is wrong: the cap cut the payload 39% and the modules only 12%, and what fixed the scan was drawing it twice as large. And the **typed road is authenticated by six digits and nothing else** (M74): `Mode::Pair` derives with an empty psk, so the channel is `X25519(e, S)` alone and a device must know `S` before it can seal — the QR carries it, typing cannot, and cide never printed it, so that road had never worked. The server now greets every connection with its public key in the clear *before* reading the handshake, which is a convenience and never evidence: a scanned invite pins `S` and refuses a greeting that differs, while a typed one adopts what it is handed and settles it by `Sas`, six digits expanded from the same HKDF and compared by a person. Four things here are silent if got wrong. **The digits gate the code, not the connection** — `pair()` suspends before sending `Pair { code }`, because a confirmation collected afterwards reports an attack it has already lost, and the test for it asserts the code is *still redeemable* after a refusal rather than that the refusal failed. **They are shown only where the key was not pinned**, on neither a scanned pairing nor a resume, or people learn to wave through the one screen that can fail. **cide's panel offers no Confirm button** — it cannot know whether they matched, only the person can, and `check:remote` asserts the absence. **And the modal closes on `open`, which is polled and never pushed** — a code stops being usable by being redeemed, guessed wrong or running out, and only the first is anywhere near an event (the `Paired` one, which is about a *device*), so `remote_pairing_progress` answers both halves in one round trip and `a_redeemed_code_is_no_longer_outstanding` is what keeps the first true; the panel closes only a window it has watched open, or an answer already in flight when the code was minted closes it before anybody sees it.
