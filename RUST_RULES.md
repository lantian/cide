# Rust: конвенция машинно-проверяемой видимости и связности

Свод правил, оптимизирующий кодовую базу под локализацию агентом (греп + `find-references`) при сохранении человеческих конвенций именования. Каждое правило имеет механизм принуждения; правило без гейта считается отсутствующим.

Обозначения гейтов: **rustc** — проверяет компилятор; **clippy** — стандартный лint; **dylint** — кастомный лint (крейт `dylint`); **script** — скрипт в CI/pre-commit; **manual** — только ревью (таких стараемся не иметь).

---

## 0. Почему Rust — удачный носитель для этой идеи

Центральный элемент прошлого обсуждения — декларируемый allowlist точек вызова, проверяемый компилятором, — в Rust существует нативно: `pub(in crate::path)`. Это не комментарий, не сгенерированный сайдкар и не внешний линтер, а часть системы типов. Устареть не может по построению.

Второй элемент — детерминированные границы — тоже нативен: граф зависимостей Cargo. Вызов через границу слайса физически невозможен без правки `Cargo.toml`, то есть без явного, видимого в диффе акта.

Поэтому основная работа здесь — не изобретать механизм, а **закрыть те места, где Rust позволяет символу исчезнуть из исходника**.

## 1. Видимость как allowlist (ядро конвенции)

| № | Правило | Гейт |
|---|---|---|
| 1.1 | Голый `pub` запрещён везде, кроме фасадного файла крейта (`lib.rs`). | dylint |
| 1.2 | `pub(crate)` запрещён как значение по умолчанию. Каждый неприватный элемент объявляет **наименьшую достаточную** область: `pub(super)` → `pub(in crate::billing)` → `pub(crate)`. | dylint + ревью |
| 1.3 | Любое расширение области видимости — отдельный коммит, не смешанный с функциональной правкой. | script (диффует набор `pub(in ...)`) |
| 1.4 | Публичная поверхность крейта фиксируется снапшотом; изменение требует принятого файла-дельты. | `cargo public-api` в CI |

`pub(in crate::billing)` читается ровно как «звать могут только отсюда». Новая точка вызова снаружи — **ошибка компиляции**, а не замечание на ревью. Обратная связь замыкается внутри сессии агента.

Сообщение об ошибке — основной канал передачи архитектуры. Там, где rustc сам по себе недостаточно нагляден, добавляем `#[diagnostic::on_unimplemented]` или обёртку-трейт с осмысленным текстом: агент должен из ошибки узнать, где лежит декларация и что значит её расширить.

## 2. Слайсы и граф зависимостей

```
crates/
  billing/            # реализация, никто не зависит напрямую
  billing-api/        # типы, трейты, ошибки. Без логики.
  payments/
  payments-api/
  app/                # единственный бинарь, wiring
```

| № | Правило | Гейт |
|---|---|---|
| 2.1 | Один вертикальный слайс = один крейт. Горизонтальные слои (`models`, `services`, `handlers`) как крейты запрещены. | script |
| 2.2 | Слайс-крейт не может появиться в `[dependencies]` другого слайса. Разрешён только соответствующий `*-api`. | script по `Cargo.toml` (~20 строк) |
| 2.3 | `*-api` крейт не содержит исполнимой логики: только типы, трейты, ошибки, константы. | script (запрет `impl` с телом длиннее N, кроме `From`/`Display`) |
| 2.4 | Общий крейт `common`/`shared`/`utils` запрещён. Дублирование между слайсами допустимо. | script |

Смысл 2.2: blast radius правки ограничен графом зависимостей, а не дисциплиной. Это то, чего греп не даёт в принципе, а измерения показывают, что именно мультимодульные задачи — главная болевая точка агента.

## 3. Файлы и имена: glob как символьный поиск

| № | Правило | Гейт |
|---|---|---|
| 3.1 | `mod.rs` запрещён. Только `foo.rs` + каталог `foo/` (edition 2018+). | script |
| 3.2 | Один основной публичный элемент на файл. Имя файла = `snake_case` имени элемента: `PaymentRetryPolicy` → `payment_retry_policy.rs`. | dylint |
| 3.3 | Запрещены имена модулей и файлов: `utils`, `common`, `helpers`, `misc`, `types`, `base`, `core`, `manager`, `handler`, `service`, `impl`. | script |
| 3.4 | Имя типа самодостаточно и глобально уникально в воркспейсе: `BillingRetryPolicy`, не `billing::retry::Policy`. Опора на путь модуля для различения запрещена. | script (индекс имён + проверка уникальности) |
| 3.5 | `use foo::*` запрещён (кроме `mod tests`). | clippy `wildcard_imports` |
| 3.6 | `use X as Y` запрещён. Один символ — один токен во всём репозитории. | dylint |
| 3.7 | `pub use` (ре-экспорт) разрешён только в `lib.rs` фасада. В остальных местах у типа появляется второй путь, и греп начинает врать. | dylint |

3.1 — это ровно проблема «сорока файлов `handler.py`»: в типичном Rust-проекте `mod.rs` встречается десятки раз и полностью бесполезен для локализации. 3.4 стоит человеческого дискомфорта: `Policy` внутри `billing::retry` читается элегантнее, но `rg 'Policy'` возвращает мусор, а `rg 'BillingRetryPolicy'` — точку.

## 4. Анти-магия: места, где Rust прячет символ

Это предусловие для всего раздела 1: `find-references` надёжен ровно настолько, насколько код статически разрешим. Гейт обязан **падать закрыто** на неразрешимых ссылках, а не молча пропускать их.

| № | Правило | Гейт |
|---|---|---|
| 4.1 | Конструирование идентификаторов запрещено: `paste!`, `concat_idents!`, любые `macro_rules!`, порождающие элементы с производными именами. | dylint + script (запрет крейта `paste`) |
| 4.2 | Авторегистрация запрещена: крейты `inventory`, `linkme`, `ctor`, `#[ctor]`. Реестры — явные `const` массивы в одном файле. | `cargo-deny` (bans) |
| 4.3 | Proc-macro derive — по белому списку (`serde`, `thiserror`, `Debug`, `Clone`, …). Свои derive-макросы, порождающие новые именованные элементы, запрещены. | `cargo-deny` + dylint |
| 4.4 | Blanket impl (`impl<T: Foo> Bar for T`) в first-party крейтах запрещён. | dylint |
| 4.5 | `impl` блоки живут в файле определяющего типа. Разнесение impl-ов по репозиторию запрещено. | dylint |
| 4.6 | `dyn Trait` разрешён только на объявленных швах (список в `wiring.rs`). Внутри слайса — конкретные типы, чтобы `find-references` был точным. | dylint |

### 4.7. Неявные конверсии ошибок — отдельный пункт

Оператор `?` вызывает `From`, которого нет в исходнике. Это самая частая в Rust причина ответа «непонятно, где произошло преобразование».

- Внутри слайса `?` с неявной конверсией разрешён.
- **Через границу слайса** — запрещён: требуется явный `.map_err(BillingError::from_payments)` с именованным конструктором.
- Все `impl From<X> for Y` для ошибок живут в `errors.rs` соответствующего `*-api` крейта, в одном месте.

Гейт: dylint. Цена — многословность; выигрыш — путь ошибки становится грепаемым от места возникновения до места обработки.

### 4.8. Обязательные аннотации типов

`let x = thing.parse()?;` не содержит имени типа. Аннотация обязательна для результатов: `parse`, `collect`, `into`, `try_into`, `default`, `from_str`, `deserialize`.

```rust
let policy: BillingRetryPolicy = raw.parse()?;   // ok
let policy = raw.parse()?;                        // ошибка линта
```

Гейт: dylint. Людям это кажется шумом — это и есть та самая точка расхождения, где мы сознательно платим удобством человека за адресуемость.

## 5. Уникальные токены ошибок

Каждый вариант ошибки несёт стабильный код, уникальный во всём воркспейсе:

```rust
#[derive(thiserror::Error, Debug)]
pub enum BillingRetryError {
    #[error("E-BILLING-0042: retry budget exhausted for invoice {invoice_id}")]
    BudgetExhausted { invoice_id: InvoiceId },
}
```

| № | Правило | Гейт |
|---|---|---|
| 5.1 | Каждый вариант ошибки имеет код `E-<SLICE>-<NNNN>`. | dylint |
| 5.2 | Коды глобально уникальны и никогда не переиспользуются после удаления. | script (реестр `error-codes.toml`, аппенд-онли) |
| 5.3 | Строка `#[error(...)]` не собирается из фрагментов; код — литерал. | dylint |

Эффект: лог или стектрейс из продакшена → `rg 'E-BILLING-0042'` → ровно один файл, ноль промежуточных шагов. Это самый дешёвый по цене внедрения пункт всей конвенции.

## 6. Бюджет чтения

| № | Правило | Гейт |
|---|---|---|
| 6.1 | Файл ≤ 400 строк. Функция ≤ 60 строк. | script + clippy `too_many_lines` |
| 6.2 | Тесты выносятся в файл-сосед, чтобы не съедать бюджет основного файла. | script |

```rust
// payment_retry_policy.rs
#[cfg(test)]
#[path = "payment_retry_policy.test.rs"]
mod tests;
```

Атрибут `#[path]` здесь легален и решает конфликт между идиомой `#[cfg(test)] mod tests` в теле файла и лимитом на размер. Побочный выигрыш: `rg` по тестам и по коду разделяются.

## 7. Швы за пределами Rust

Там, где `find-references` слеп по построению (HTTP-роуты, SQL, ключи конфигов, топики очередей, вызовы из другого сервиса), символ-якорь ставится вручную и **кросс-проверяется** против внешнего артефакта:

```rust
/// @seam:http POST /v1/payments/{id}/retry
/// @seam:sql  billing.retry_attempts
pub(in crate::billing) fn retry_payment(/* … */) { }
```

| № | Правило | Гейт |
|---|---|---|
| 7.1 | Каждый обработчик роута несёт `@seam:http`, сверяемый с OpenAPI-спекой. | script |
| 7.2 | Каждая таблица/вью, к которой обращается слайс, несёт `@seam:sql`, сверяемый с миграциями. | script |
| 7.3 | Элемент, участвующий в динамическом шве без `@seam`, — ошибка сборки. | script (fail closed) |

Это единственное место, где допускается рукописная аннотация, и она допускается ровно потому, что для неё есть внешний источник истины для сверки.

## 8. Wiring

| № | Правило | Гейт |
|---|---|---|
| 8.1 | Вся сборка графа объектов — в `app/src/wiring.rs`. Конструирование зависимостей в других файлах запрещено. | dylint |
| 8.2 | DI-контейнеры и сервис-локаторы запрещены. Только явные конструкторы. | `cargo-deny` |
| 8.3 | Реестры (роуты, команды, миграции, воркеры) — явные `const` срезы в одном файле на реестр. | dylint |

## 9. Стек принуждения

```
lib.rs           →  #![deny(...)] на весь набор clippy-правил
clippy.toml      →  пороги
dylint/          →  кастомные линты (правила 1.1–1.2, 3.2, 3.6–3.7, 4.x, 5.x, 8.x)
deny.toml        →  запрещённые крейты (paste, inventory, linkme, ctor, DI)
xtask/           →  script-правила: mod.rs, размеры, уникальность имён и кодов,
                    граф зависимостей слайсов, швы
```

Единая точка входа: `cargo xtask check`. Она должна быть:

- **быстрой** (< 20 c на инкрементальном запуске), иначе агент перестанет её звать;
- **вызываемой самим агентом** — повешенной на `PostToolUse`-хук и указанной в `CLAUDE.md` первой строкой;
- **actionable в выводе**: не «visibility violation», а «`BillingRetryPolicy::apply` объявлен как `pub(in crate::billing)`; вызов из `crates/payments/src/settlement.rs:88` запрещён. Либо используйте `billing-api::RetryPort`, либо расширьте декларацию в `crates/billing/src/payment_retry_policy.rs:12`.»

Без последнего пункта конвенция превращается в налог: агент пишет нарушающий код, узнаёт об этом от человека на ревью, и вы платите за дисциплину вручную.

## 10. Порядок внедрения

Разделы упорядочены по убыванию отношения эффект/цена:

1. **§5** (коды ошибок) и **§3.1, 3.3, 3.5** — чистые запреты, день работы, немедленный выигрыш в грепабельности.
2. **§6** (бюджет чтения) и **§3.2** — механическая правка, скриптуемая.
3. **§2** (слайсы) — самая дорогая часть, но именно там сидит основной эффект.
4. **§1** (видимость) — требует §2 как основы.
5. **§4** (анти-магия) — предусловие корректности §1; вводится вместе с ним, но на новый код через `#[allow]`-амнистию для старого.
6. **§7** (швы) — последним, когда остальное стабилизировалось.

## 11. Честные издержки и что из этого не измерено

Осознанно принимаемая цена:

- **§4.7 и §4.8** — самые болезненные для человека пункты. Многословность растёт заметно.
- **§3.4** — длинные имена типов конфликтуют с эстетикой Rust, где путь модуля традиционно несёт часть смысла.
- **§2** — рост числа крейтов бьёт по времени компиляции; частично компенсируется распараллеливанием сборки, частично нет.
- **§9** — dylint требует поддержки при обновлении toolchain.

**Ничего из перечисленного не измерено на Rust.** Существующие данные (минимальные пары SonarSource) получены на Java и Python, мерили «чистоту», а не эти конвенции, и показали неизменный pass rate при сокращении следа. Правдоподобная гипотеза здесь — что §1–§2 сдвинут локализацию, а §3–§6 сдвинут след, но это гипотеза.

Если проверять — проверять методологией минимальных пар: поведенчески эквивалентный вариант одного реального сервиса по этим правилам, 25–30 задач, сформулированных в терминах внешнего поведения без указания файлов, скрытые тесты на публичной поверхности, по 10 прогонов на сторону. Первичная метрика — acc@5 по локализации и число повторных заходов в файл, а не токены: они двигаются раньше и с меньшим шумом. Разброс между прогонами одной задачи достигает 2.5×, поэтому на пяти прогонах измеряется шум.
